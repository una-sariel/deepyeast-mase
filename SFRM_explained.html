v9 RSB vs v10 SFRM

老师「随机森林 + 随机遮盖」的两个实现 · DeepYeast / MaSE

v9 = 每张图独立随机 patch + 投票 · v10 = 整批共用一块区域（原 SFRM）

一句话：v9 学随机森林的 feature bagging + 投票（每张图不同 mask，测试平均 R 次）； v10 学草图的 all image 同一 region（每个 epoch 所有训练图挖同一块，测试不挖）。 都是一份 CNN 权重，不是 sklearn RF。

1. 为什么要这样改写老师的想法

草图里同时出现了：样本子集、一排「树」、CNN、以及红框里的「Random select a region for all image」。

草图元素不宜直接做的收成的可实现版本
Random Forest 在像素上端到端训 sklearn RF，并和 CNN 反传耦合 用 随机空间区域 模拟「随机特征子集」
对所有图选同一区域 语义模糊（何时选？多大？） 每个 epoch 采样一次，该 epoch 训练集共享
多棵树 → 多个 Ŷ → Bagging 默认训 M 份大 CNN（贵，且与「单模型」冲突） 优先：一个网络 + 多窗推理投票
定位：方法/正则消融线，和「可学习 selector」对照；不保证单独冲到 90%，但协议清晰、好写进论文/汇报。

2. SFRM：共享随机区域遮挡（训练）

训练期在 \(64\times64\) 图上采样一个边长为 \(S\) 的轴对齐矩形，把窗内两通道像素置 0。

图 1 · 「共享」指相对坐标相同，不是遮住同一细胞内容。每张图内容不同，但被挖掉的是同一块空间位置。

和普通 Cutout 差在哪？

常见 CutoutSFRM（本协议）
窗怎么采 每张图 / 每个 batch 各自随机 每个 epoch 一次，训练集共用
动机 强数据增强 对齐老师「all image 同一 region」+ RF 式子空间
Val 通常不遮 不遮（对齐主测试：全图）

训练循环（逻辑）

# 每个 epoch 开始
r = randint(0, 64 - S)
c = randint(0, 64 - S)

# 该 epoch 所有 train batch
for x, y in train_loader:
    x = x.clone()
    x[:, :, r:r+S, c:c+S] = 0   # 两通道一起遮
    loss = criterion(model(x), y)
    ...

# 验证：不遮
val_acc = evaluate(model, val_loader, mask=None)

3. 多窗投票（推理，单模型）

推理期 · 可选仍然只有 一份 best.pt。对每张测试图做多次前向，再平均概率。

图 2 · 多窗投票 = 测试时 TTA 的一种；视图是「随机挖洞」而不是翻转。权重文件仍只有一个。

具体数字例子（DeepYeast）

  • 图像 \(64\times64\)，窗边长 \(S=24\)
  • 训练：每 epoch 共享一窗（SFRM）
  • 测试：1 次全图 + \(M=7\) 次不同随机窗 → 共 8 次 forward，概率平均
  • 窗位置用固定随机种子预采样，保证可复现
和「森林投票」的类比：每棵「树」≈ 同一网络在某一种遮挡视图下的预测； 平均概率 ≈ 软投票。并没有真的训出多棵决策树。

4. 真·袋装 vs 多窗投票

多窗投票（优先）

  • 1 份权重
  • 训练成本 ≈ 原来 ×1
  • 测试成本 ≈ ×(M+1)
  • 符合「单模型」约束

真 Bagging（可选）

  • M 份权重（如 5 个 CNN）
  • 训练成本 ≈ ×M
  • 每成员可用不同窗序列 / bootstrap 样本
  • 更贴草图「一排树」，但更贵

建议汇报口径：先做 SFRM 训练 + 多窗投票；只有老师坚持「多模型森林」再上真 Bagging。

5. 和 MaSE selector / Flip-TTA 的差别

机制谁决定「看哪 / 不看哪」随图变化？阶段
MaSE learned selector 网络学 patch 重要性（top-k） 是（每张图不同） 训练+推理（可微）
SFRM 随机固定矩形 训练：同 epoch 全员相同；推理多窗：每视图不同 增强 / 视图定义
Flip / rot90 TTA 几何变换 是（变换后） 仅推理
消融纪律：第一版不要把 SFRM 和 learned selector 叠在一起，否则涨跌说不清。 先关 selector 测纯 SFRM，再与 MaSE 主结果对照。

多窗投票可以和 flip_rot 以后组合，但算力会相乘；先各自报一行。

推理伪代码

windows = [(r_i, c_i) for i in range(M)]  # 固定种子预采样
probs = []
probs.append(softmax(model(x)))             # 全图
for (r, c) in windows:
    z = x.clone()
    z[:, :, r:r+S, c:c+S] = 0
    probs.append(softmax(model(z)))
y_hat = argmax(mean(probs))

7. 实验怎么报、成功标准

建议至少报两行（与现有 TTA 习惯一致）：

  1. SFRM 训练 → 全图测试（主协议）
  2. SFRM 训练 → 多窗投票测试（可选增益）
对照看什么
无遮挡 baseline（同架构）SFRM 是否严重掉点
Per-image 随机窗（每张图自己的窗）「共享」是否必要
MaSE learned selector方法对照主结果
宽松成功标准（方法验证）：全图 test 相对 baseline 掉点 ≤ ~0.3pp，或加上多窗投票有小幅提升，且训练稳定。
不要预期：单靠 SFRM 一定超过 v4 / P2.5+TTA 的 89.8%。

8. 常见疑问

Q：会不会总挡住细胞？

单个 epoch 可能挡住关键区域，但窗位置跨 epoch 均匀随机；S 太大（如 32）时风险更高，优先 16–24。

Q：为什么验证集不遮？

主测试协议是「看全图」。Val 不遮才能选出在全图上最好的 checkpoint；多窗投票是第二行指标。

Q：这还算 Random Forest 吗？

算精神上的 RF（随机子空间 + 投票），不是字面决策树森林。论文/汇报里应写清楚，避免审稿人误解成 sklearn RF。

Q：和冲 90% 精度主线什么关系？

并行线。精度主线仍是：强 frozen ckpt（v4 级）→ 极轻量解冻 → flip_rot TTA。SFRM 用来落实老师的 mask/RF 想法并作消融。

Q：下一步若要写代码？

在训练循环加 epoch 级 (r,c,S)；在 eval 加 --sfrm-windows N。需要时可再单独做 run 文档给老师机器。
